## 設計判断 (確定した事実)

- **UGH の入力に固有情報はない**: `compute_snapshot_statistics` の 5 統計量 (momentum_5d、
  spot_vs_sma20、前日変化 ÷ trailing、range_expansion、directional_consistency)。単純テクニカル
  (sign(SMA5−SMA20) × trailing) と前日方向は UGH の入力そのもの。問いは「変換の価値」。
- **方向の腕は実在**: β 非 FLAT 日の的中 60% (64 日 30/50、1 月〜10 月の v2.7 再計算 101/167)、
  単純テクニカルと割れた日は 10–2 (64 日) / 25–10 (1 年)。源泉は price_implied (β p_weight 0.40)
  が SMA の符号を上書きする反転直後の日。α (p 0.20) は割れが 4 日しかなく capture −540bp。
- **conviction は逆相関**: β 1 年再計算で conviction <0.4 は 78% 的中・capture +884bp・平均
  |予測| 5.3bp、≥0.8 は 53%・−689bp・16.9bp。magnitude が conviction に比例するので方向の価値が
  損益に出ない。合議型 (4/4 一致) は高 conviction 日の部分集合 = 最悪。
- **FLAT は判断ではない**: |e_star × trailing × 係数| ≤ 3bp の閾値。符号衝突日 = 反転翌日で、
  値動きは平均並み (34.5 vs 33.4bp)。自分の符号で賭けるより良い (2/14) が、ST 比では中立。
- **Range 的中率と state は UGH の証拠にならない**: range は spot ± 1.25 × trailing range で
  e_star 非依存、state は `build_ugh_variant_forecast` が参照しない (記録のみ)。
- **MAE は方向情報を検出できない**: 60% 的中でも定数 k=3bp しか RW に勝てない。capture /
  |Δ| 加重 / 共通日 excl-FLAT で測る。
- **売買試算の順位は政策ショック日で決まる**: 2026 年 |Δ|>110bp の 8 日 (7 日が円高方向)。
  63 日の SE ≈ 3%、199 日でも |t| ≤ 1.3。GPT-M3 +8.06% (1 月〜10 月、3 四半期連続プラス) は
  28 マスの格子から選ばれた 1 マス (隣の g=1 は期間外 −6.4%)、採用根拠にならずベンチマーク扱い。
- **1 日遅延方式は別仮説の検証**: 予測の情報集合は 08:00 で閉じている (alpha の `current_spot`
  は直近完了窓の終値)。未来情報ではなく約定価格の問題。正直な検証には公開時刻の spot が要る。
- **執行層の設計方針**: 予測器と売買を分離。方向は β、サイズは vol 目標 (30bp) とショック
  フィルタ (前窓 > 2.5 × trailing)、conviction は使わない。6 book を `execution_version = x1` で
  凍結し前向き観測、合格ゲート (100 取引・6 か月・t ≥ 2・DD ≤ 10%・ベンチ超え)。
  spec `docs/specs/fx_execution_layer_v1.md`、brief FX-EXEC-LAYER / FX-EXEC-REPORTING。

- セルフレビューに **実データ copy の smoke test** を加えた: `fx-daily-data` の `csv/` を scratchpad に copy し、
  backfill (dry-run → 本実行 → 再実行で byte 不変) と weekly / monthly pipeline を走らせ、時計を 10/20 に進めて

  `Skips` セルが `|` 区切りで表を壊す) を 1 件拾った。
- Codex の 4 rounds は全件「batch 内 / ファイル間の metadata 混在を先頭行に丸めない」の同一系統。round 1〜3
  (版・as_of・窓・outcome の一致、backfill の重複 kind / 別窓行 / 読めないファイル / already_complete の
  belonging) は小さく局所的なので採用。round 4 (評価行の side/size を判断行と列ごとに突合、backfill の
  ファイル間 key 比較) は「判断ファイルは上書きされず評価は判断行から導出される」ので手編集でしか生じない
  経路と判断し、**変更なし + follow-up** (評価の再導出 diff = archive 検証モードとして別 brief) で締めた。
  線引きの基準: identity (batch id・版・窓・outcome) は見る、payload の写し違いは再導出で検証する別機能。
- monthly artifact のラベルは窓の最終日の月 (`execution/monthly/202609`)。既存 `analytics/monthly/202610`
  (review 日の月) と 1 か月ずれるが、データ月で引く方が report ファイル名 (`fx_monthly_report_202609`) と
  一致するので採用し spec §8.5 に記載。揃えるなら 1 行。
- 金曜 block の執行層 step は weekly v2 の `[OK]` の後、独自 try/except。weekly v2 自体が落ちた夕方は
  月曜 pipeline が再生成する (spec §8.6)。
