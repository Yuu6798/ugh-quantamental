## 設計判断

- **方向ロジックは変えない**: 147 評価日 (4/1〜11/6) × 4 variant の replay で、方向入力 (technical / fundamental /
  前日変化) の符号的中は 51〜53%、「常に up」が 64.6%。UP 判定の的中は上昇ドリフトと同じ。事前登録した方向側の
  候補 (alignment の q ペア除去 AL1、gravity 0 / 符号化) はすべて方向悪化。自動 flag (collapse) は slice が月の
  100% / 83% で blended の再掲。
- **v2.8 は magnitude 経路だけ**: 方向・FLAT は v2.7 の結合係数で判定のまま (v2.5 以来の sign/FLAT 不変量を延長)、
  非 FLAT の記録値の係数を 9 月に事前登録した 0.75 に (`magnitude_conviction_weight`、default 0.0、w = 1.0 で v2.7 を
  bit-for-bit 再現)。9 月 mode D (FLAT も定数で判定) は FLAT 集合が変わって β −3・δ −2 的中 → 不採用。
- **縮小効果と前例は隠さず判断材料にした**: 改善 (−0.33〜−0.43bp) の約 3/4 は平均的な縮小 (平均をそろえた
  decouple 単独は −0.09〜−0.14bp)、平均 magnitude 誤差は +0.17〜+0.22bp 悪化。7 月 §5.6 (置換 5 案が close error を
  改善せず結合を残した) と 9 月 §5.3 (縮小が主の案を退けた) との緊張を findings §4.4・PR 本文に明記し、
  「見送るなら engine commit を外して docs だけ merge」を選択肢として提示 → ユーザーは v2.8 を採用。
- **執行層 live 建値ドリフトは現状維持**: 21 窓で平均 |ドリフト| 22.1bp、窓変化との相関 0.84。評価窓の変更は
  governance spec §5.2 の固定項目 (予測の確定時刻・horizon)、run 時刻は GitHub 側の遅延次第。
- **CC-M03 は rejected**: v2 の UGH forecast は `disconfirmers=()` で作られ、集計を足しても常に空。

## 成功パターン

- **事前登録 + 時期分割**: 0.75 を 9 月の定義のまま使い、設計期間 (4〜9 月) と事前登録後 (10/1〜11/6) を分けて
  同じ大きさの改善を確認した。
- **改善の分解に対照を置いた**: 一律縮小 (平均 |予測| を合わせる) と平均をそろえた decouple の 2 つで、縮小分と
  重み付け除去分を切り分けた。最初の「結合係数の平均で decouple」は縮小を少し含んでおり、セルフレビュー後に
  平均 |予測| をそろえる形に直した。
- **完全一致の照合**: 本番 272 件が `==` で再現されることを確かめ、replay script の照合を許容誤差なしに締めた
  (CSV は float を repr で書くので round-trip が厳密)。
- **独立セルフレビュー agent**: P1 0・P2 1 (spec §5.1.1 の FLAT 規則が永続値ベースの記述のまま) と P3 群
  (magnitude 誤差の未記載、calm-day テストが v2.7 以降空振り、中間重みのテスト欠如、rollback 条件の範囲の不一致) を
  指摘。その反映中に 7 月 §5.6 の前例を読み直して突き合わせを追加した。
