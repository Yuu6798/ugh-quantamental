## 今週の構造的観測: live 系列が測っているのは forecast の窓ではない

執行層の最初の live 判断 (10/8) は、daily run が走った **21:07 JST (12:07:34Z) の yahoo live spot
158.274** を建値にしている。forecast の窓は 10/8 08:00 JST に始まり、その始値は 158.03。つまり
発行から 13 時間、ドル円が +24.4pips (15.4bp) 上げた後に `up` の判断を建てたことになり、同じ日の
損益は

| 系列 | 建値 | 終値 (10/9 08:00 JST) | 損益 | コスト |
|---|---|---|---|---|
| bar (= forecast の窓) | 158.03 (始値) | 157.86 | **−10.8bp** | 0.63bp |
| live (ugh_x1、size 0.806) | 158.274 (21:07 JST) | 157.86 | **−26.2bp** (size 込み −21.6bp) | 0.63bp |

に分かれた。2 日目の 10/9 も建値は **158.264 (20:59 JST)** で、08:00 JST 時点の直近終値 157.86
より 40.4pips (25.6bp) 上。cron の実測遅延 (+5h54〜+8h47、運用ヘルス 3) で run が JST 夜に着地する
限り、live の exposure は「東京・ロンドンを通過した後の NY 時間帯 (約 11 時間)」であり、遅延が
ゼロでも初回 run は 14:23 JST で、始値 → 建値のドリフトは必ず live から除かれ bar には含まれる。

これは spec §4 (判断時の live spot で建てる) どおりの挙動であって不具合ではないが、含意が 2 つある:
(1) live と bar の差は slippage ではなく「08:00 → 建値のドリフトの符号」で決まる。今週の 2 日は
どちらも上昇後の高い建値で、`up` に対して逆風だった。(2) ゲートの t 値は live 系列で測るので、
合格ゲートが検定する仮説は「UGH の方向が NY 時間帯の値動きを当てるか」であり、forecast の 24 時間
方向率 (今週 50%) とは別物。ドリフトに符号の偏りがあるか (UGH が `up` を出す日の東京時間は上がり
やすいか) は、`execution_evaluation.csv` の `entry_price_live − realized_open` を live 日が 20 日ほど
溜まった時点で集計すれば再計算なしに分かる (→ 持ち越し 2)。それまでは live の損益を bar と並べて
読み、単独で評価しない。
