(Warsh)、日銀は 9 月利上げ観測 (東京 CPI・全国 CPI の推移)。金利差の行方が

## 運用ヘルス — ⚠️ インシデント 2 件 (確認済みの 8/17–8/21 週報の「安定稼働」記載を訂正)

### 1. Gmail 認証エラーで確認済みの 8/17 以降メール通知が不達 + 全 run が赤

`fx-daily-protocol.yml` のメール通知 step が **Gmail SMTP `535 BadCredentials`** で
失敗し続けている (確認できた範囲で 8/17 以降の全 run、それ以前は未確認)。protocol
本体はデータを正常に生成・push しており、**provider_health.csv 上は健全に見えるが、
Actions の run conclusion は全て failure**。影響は 2 つ:

- **ユーザーへの日次メール通知が届いていない** (少なくとも 2 週間)。
- 全 run が赤のため、**本物の欠落 (下記 2) が赤の中に埋もれて検知できなかった**。

~~要ユーザー対応: Gmail アプリパスワードの再発行と `MAIL_PASSWORD` 更新~~ —
**この対応は 2026-08-29 のユーザー判断で見送りが確定し、実施しない** (メール通知は
廃止、通知は GitHub-native 経路へ一本化)。実施済みの修復は、通知失敗が run 全体を
赤にしないようにする mail step への `continue-on-error: true` 追加 (本レポートと
同じ branch、マージで有効化) のみ。

過去 2 週の週報の「安定稼働 (failed 0)」は provider 層のみを見た誤記載であり、
撤回する。skill にも「運用ヘルスは provider_health と Actions conclusions の 2 層で
確認する」を追記した。

### 2. GitHub Actions スケジューラ遅延で 8/28 (金) の daily run が欠落

8/27 と 8/28 の cron (05/07/11 UTC) が **約 11 時間遅れて発火** (リポジトリ側の変更は
なし — プラットフォーム側の遅延)。結果:

- 8/27 分: 遅延したが JST 金曜のうちに実行され、lag フラグ付きで forecast 発行済み
  (provider_health の lag 3 件はこれ)。
- 8/28 分: 3 run とも **JST 土曜 (8/29 02:16 / 04:14 / 06:17)** に着地し、business-day
  ガードが正しく拒否 → **8/28 の forecast 発行なし・8/27 分の評価なし・週次 artifact
  生成なし**。
- 週次 artifact はローカル再生成で代替 (ブランチ非接触)。**8/27 発行分の評価は月曜の
  通常 run では拾われない設計** (`previous_window_matches` は直前 window のみ対象) の
  ため、放置すると恒久欠測になる — 持ち越し 2 で追跡。

provider 層自体は healthy (12 runs / failed 0 / fallback 3・lag 3 は遅延由来)。
