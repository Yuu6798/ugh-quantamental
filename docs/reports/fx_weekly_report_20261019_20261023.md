## 今週の構造的観測: provider の日足遅延が forecast を 1 日消し、執行層ゲートの除外機構を初めて呼ぶ

これまでの Saturday artifact 欠落 (8/29・9/5・9/12) はすべて **cron 遅延**で最終 retry が JST 土曜に落ちた
ケースで、#130 の繰り越し経路 (金曜の完全 batch があれば `as_of` を金曜に戻す) が 10/16 まで 5 週連続で救って
きた。今週は別の経路で落ちた:

1. 10/23 (金) 19:16 JST の初回 run で、alpha_vantage の最新完了窓が **10/22 08:00 のまま** (10/23 の日足が未公表)。
   #135 の規約どおり `as_of` を 10/22 に繰り下げ → 10/22 batch は既にあるので `idempotent_skip`。21:41 JST の
   2 回目も同じ。この時点で 10/23 の forecast は存在しない。
2. 00:47 JST (土) の最終 retry は 10/24 が営業日でないため #130 の繰り越し経路に入るが、**繰り越す先の 10/23
   batch が無い**ので `_fail`: 「Today (2026-10-24 JST) is not a protocol business day, and the previous business
   day (2026-10-23 JST) has no complete forecast batch to carry over.」
3. 結果: 10/23 の forecast・判断は永久に無い (catch-up は outcome を埋めるが forecast は作らない)、10/22 の
   outcome は日足が出るまで未確定、weekly v2 と執行層 artifact は生成されない。PRICE-ALERT の stall 検知
   (22:45 JST「no 2026-10-23 forecast」) は正しく発報した。

含意は 3 つ。(a) **運用**: 遅延が原因でなく provider 側の公表遅れなので、cron を早めても防げない。金曜に
provider が遅れた場合の第 3 の経路 — 最終 retry で yahoo fallback に切り替えて 10/23 の bar を取る、または土曜
朝に 1 回だけ「金曜 as_of の forecast を発行する」retry を置く — を brief 候補にする (9/29 の yahoo 退化 bar
問題と同じ fallback 品質の論点に当たるので、両方を 1 つの brief で扱う)。(b) **執行層ゲート**: 10/23 は
activation 後の営業日で判断 batch が無いので、10/26 08:00 JST 以降 `missing_decisions` + `missing_live` で
block される。spec §9 の設計どおり **`EXECUTION_EXCLUDED_AS_OF` に `date(2026, 10, 23)` を「provider 日足遅延で
forecast 未発行」の理由付きで登録した (spec §12.2 に根拠を記録)** — 除外機構の初回適用。backfill では埋まらない
(forecast 行が無い)。(c) **月次**: 10 月の営業日 1 日が forecast ごと欠ける。10 月月次
(11 月) の分母に注記が要る。

## スライス別の傾向

- **regime**: 評価済み 3 日とも trending (choppy 標本ゼロは **17 週目**)。10/22 の急落日は未評価。
- **volatility**: 3 日とも `normal`。

## 運用ヘルス

### 1. 金曜に forecast が出ず、Saturday artifact の自動生成が 6 週目で途切れた

`fx-daily-protocol.yml` は 10/19–10/23 に **14 run success + 1 failure** (10/23 15:47:20Z = JST 10/24 00:47
開始の最終 retry、`run-daily-protocol` の「Run FX daily protocol」step で停止、push 以降は skipped)。失敗
メッセージは構造的観測のとおり、繰り越し先の 10/23 batch が無いことによる営業日ガード。原因は 10/23 の
